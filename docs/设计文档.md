# 请假审批系统（OA）— 业务与接口设计

> DDD 练习项目配套设计文档。后端代码由你手写，本文档定义业务规则、领域模型建议与全部接口的入参/出参。

---

## 1. 业务场景概述

员工提交请假申请，部门主管审批，审批通过后扣减对应假期余额；支持撤回、取消、销假等全生命周期管理。

### 1.1 参与角色

| 角色 | 编码 | 职责 |
|------|------|------|
| 员工 | `STAFF` | 创建/编辑/提交请假单，撤回，取消，查看余额 |
| 主管 | `MANAGER` | 审批（通过/驳回）下属请假单，同时拥有员工全部能力 |

> 练习项目不做真实登录鉴权。前端通过请求头 `X-Employee-Code` 传递"当前用户"，后端据此识别身份（模拟登录）。

### 1.2 假期类型

| 类型 | 编码 | 说明 |
|------|------|------|
| 年假 | `ANNUAL` | 每年固定额度 |
| 病假 | `SICK` | 每年固定额度 |
| 事假 | `PERSONAL` | 每年固定额度 |

### 1.3 请假单状态机（核心领域规则）

```
DRAFT（草稿）
  │ 提交 submit
  ▼
SUBMITTED（已提交）──→ 撤回 withdraw ──→ DRAFT（回到草稿，可再编辑）
  │ │
  │ └─→ 审批通过 approve ──→ APPROVED（已通过，扣减余额）
  │        │
  │        ├─→ 取消 cancel（开始日之前）──→ CANCELLED（已取消，回滚余额）
  │        └─→ 销假 close ──→ CLOSED（已销假/已完结）
  │
  └─→ 审批驳回 reject ──→ REJECTED（已驳回，终态；重新请假需新建请假单）
```

状态编码：`DRAFT` / `SUBMITTED` / `APPROVED` / `REJECTED` / `CANCELLED` / `CLOSED`

> 这个状态机正好可以落在你项目里已有的 `StatusMachine` 接口上：每个状态枚举实现 `getFlowToCollection()` 声明合法流转，`flowTo()` 校验非法流转并抛异常。

### 1.4 业务规则（领域层校验，全部在后端执行）

1. **余额校验**：提交时校验对应年度假期余额充足；审批通过时扣减余额；取消时回滚余额。（可进阶：提交时预占、通过时正式扣减）
2. **时长计算**：请假时长 = 起止日期的自然日天数（`endDate - startDate + 1`）。进阶练习：改为工作日计算（跳过周末），作为领域服务实现。
3. **时间校验**：开始日期不得早于提交当日；结束日期不得早于开始日期；单次请假不超过 30 天。
4. **重叠校验**：同一员工不允许存在时间重叠且状态为 `SUBMITTED` / `APPROVED` 的请假单。
5. **操作权限**：
   - 只有申请人本人可编辑/提交/撤回/取消自己的请假单；
   - 只有 `MANAGER` 角色可审批，且不能审批自己的请假单；
   - 只能操作 `SUBMITTED` 状态的单据（审批），只能操作 `DRAFT` 状态的单据（编辑）。
6. **取消限制**：已通过的请假单只能在开始日期当天 00:00 之前取消。
7. **驳回意见**：驳回时必须填写驳回原因（1~200 字）。
8. **并发控制**：请假单更新使用乐观锁（`version` 字段），余额扣减同样需要。

### 1.5 领域模型建议（供参考，具体由你实现）

- **聚合根**：`LeaveRequest`（请假单），聚合内包含审批记录列表；code 作为聚合标识。
- **实体**：`Employee`（员工）、`ApprovalRecord`（审批记录，聚合内实体）。
- **值对象**：`LeavePeriod`（请假时间段：startDate + endDate + duration，含时长计算与重叠判断）、`LeaveType`（枚举 + 规则）、余额快照。
- **领域服务**：余额校验/扣减（跨聚合：请假单 ↔ 余额）。
- **领域事件（进阶）**：`LeaveRequestSubmitted`、`LeaveRequestApproved`（监听后扣余额）、`LeaveRequestRejected`、`LeaveRequestCancelled`（回滚余额）、`LeaveRequestClosed`。
- **仓储**：`LeaveRequestRepository`、`EmployeeRepository`、`LeaveBalanceRepository`。

## 2. 接口设计

### 2.0 通用约定

- Base URL：`/api/v1`
- 所有请求需携带请求头 `X-Employee-Code: EMP001`（模拟当前登录用户）。
- 统一响应包装：

```json
{ "code": 0, "message": "success", "data": { } }
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 0 成功；非 0 失败，见错误码表 |
| message | string | 提示信息，前端直接展示 |
| data | object/null | 业务数据，失败时为 null |

错误码约定：

| code | 含义 |
|------|------|
| 0 | 成功 |
| 40000 | 参数校验失败（message 返回具体原因） |
| 40400 | 资源不存在（员工/请假单） |
| 40100 | 未识别当前用户（缺 X-Employee-Code） |
| 40300 | 无权执行该操作 |
| 41001 | 状态流转非法（对应状态机异常） |
| 41002 | 假期余额不足 |
| 41003 | 请假时间与其他单据重叠 |
| 41004 | 请假时间不合法（开始日期过早/区间非法/超 30 天） |
| 41005 | 乐观锁冲突，请刷新后重试 |
| 50000 | 系统内部错误 |

分页请求统一参数：`page`（1 起）、`size`（默认 10）；分页响应统一结构：

```json
{ "list": [], "total": 100, "page": 1, "size": 10 }
```

---

### 2.1 获取当前用户信息

`GET /api/v1/employees/me`

**入参**：无（识别 `X-Employee-Code`）

**出参** `data`：

```json
{
  "code": "EMP001",
  "name": "张三",
  "department": "研发部",
  "role": "STAFF"
}
```

---

### 2.2 员工列表（主管审批中心用，可选做"按员工筛选"）

`GET /api/v1/employees`

**入参**：无

**出参** `data`：数组

```json
[
  { "code": "EMP001", "name": "张三", "department": "研发部", "role": "STAFF" },
  { "code": "MGR001", "name": "李总", "department": "研发部", "role": "MANAGER" }
]
```

---

### 2.3 我的假期余额

`GET /api/v1/leave-balances?year=2026`

**入参**（query）：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| year | int | 否 | 年度，默认当前年 |

**出参** `data`：数组

```json
[
  {
    "leaveType": "ANNUAL",
    "leaveTypeName": "年假",
    "year": 2026,
    "totalDays": 10,
    "usedDays": 3,
    "frozenDays": 1,
    "remainingDays": 6
  }
]
```

> `frozenDays` 为进阶方案中"提交预占、通过扣减"的中间量；简化实现可恒为 0。

---

### 2.4 创建请假单（草稿）

`POST /api/v1/leave-requests`

**入参**（body）：

```json
{
  "leaveType": "ANNUAL",
  "startDate": "2026-10-01",
  "endDate": "2026-10-03",
  "reason": "国庆回家探亲"
}
```

| 字段 | 类型 | 必填 | 校验 |
|------|------|------|------|
| leaveType | string | 是 | 枚举：ANNUAL/SICK/PERSONAL |
| startDate | string | 是 | 格式 yyyy-MM-dd |
| endDate | string | 是 | 格式 yyyy-MM-dd，≥ startDate |
| reason | string | 是 | 1~200 字 |

**出参** `data`：请假单完整对象（结构同 2.6 详情），创建后状态为 `DRAFT`。

---

### 2.5 修改请假单（仅 DRAFT 可改）

`PUT /api/v1/leave-requests/{code}`

**入参**：同 2.4，另加路径参数 `code`；body 中额外携带：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| version | int | 是 | 乐观锁版本号，取详情接口返回值 |

**出参** `data`：请假单完整对象。

---

### 2.6 请假单详情

`GET /api/v1/leave-requests/{code}`

**入参**：路径参数 `code`

**出参** `data`：

```json
{
  "code": "LV20260916001",
  "applicantCode": "EMP001",
  "applicantName": "张三",
  "department": "研发部",
  "leaveType": "ANNUAL",
  "leaveTypeName": "年假",
  "startDate": "2026-10-01",
  "endDate": "2026-10-03",
  "duration": 3,
  "reason": "国庆回家探亲",
  "status": "SUBMITTED",
  "version": 1,
  "createdAt": "2026-09-16 10:30:00",
  "updatedAt": "2026-09-16 11:00:00",
  "approvalRecords": [
    {
      "approverCode": "MGR001",
      "approverName": "李总",
      "action": "REJECT",
      "comment": "项目上线期间，建议错峰",
      "createdAt": "2026-09-15 14:00:00"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | string | 请假单号，格式 `LV + yyyyMMdd + 3位序列`（生成规则由你定） |
| duration | int | 自然日天数，后端计算 |
| status | string | DRAFT/SUBMITTED/APPROVED/REJECTED/CANCELLED/CLOSED |
| version | int | 乐观锁版本 |
| approvalRecords | array | 审批记录，按时间倒序；action：APPROVE/REJECT |

---

### 2.7 我的请假单列表（分页）

`GET /api/v1/leave-requests`

**入参**（query）：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| status | string | 否 | 状态筛选，多值逗号分隔如 `SUBMITTED,APPROVED` |
| leaveType | string | 否 | 假期类型筛选 |
| keyword | string | 否 | 匹配请假单号或事由 |
| page | int | 否 | 默认 1 |
| size | int | 否 | 默认 10 |

**出参** `data`：分页结构，`list` 内为 2.6 的请假单对象（`approvalRecords` 可省略以减小体积）。

---

### 2.8 提交请假单（DRAFT → SUBMITTED）

`POST /api/v1/leave-requests/{code}/submit`

**入参**：路径参数 `code`（body 无）。提交时执行全部业务规则校验（余额、重叠、时间、权限）。

**出参** `data`：请假单完整对象。

---

### 2.9 撤回请假单（SUBMITTED → DRAFT）

`POST /api/v1/leave-requests/{code}/withdraw`

**入参**：路径参数 `code`

**出参** `data`：请假单完整对象。

---

### 2.10 取消请假单（APPROVED → CANCELLED，回滚余额）

`POST /api/v1/leave-requests/{code}/cancel`

**入参**：路径参数 `code`

**出参** `data`：请假单完整对象。

---

### 2.11 销假（APPROVED → CLOSED）

`POST /api/v1/leave-requests/{code}/close`

**入参**：路径参数 `code`。业务含义：假期结束确认单据完结（实际休假天数与申请一致时直接关闭；进阶可做"实际提前返岗按实际天数回滚差额余额"）。

**出参** `data`：请假单完整对象。

---

### 2.12 审批（MANAGER 专属）

`POST /api/v1/leave-requests/{code}/approve`

**入参**（body）：

```json
{
  "action": "APPROVE",
  "comment": "同意",
  "version": 1
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| action | string | 是 | APPROVE / REJECT |
| comment | string | 否(通过)/是(驳回) | 审批意见；REJECT 时必填 1~200 字 |
| version | int | 是 | 乐观锁版本号 |

**出参** `data`：请假单完整对象。APPROVE 成功后余额已被扣减。

---

### 2.13 待我审批列表（分页，MANAGER 专属）

`GET /api/v1/leave-requests/pending-approvals`

**入参**（query）：`page`、`size`（同 2.7），可加 `keyword`。

**出参** `data`：分页结构，`list` 为 SUBMITTED 状态的请假单对象（申请人非当前用户）。
